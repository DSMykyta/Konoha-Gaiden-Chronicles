## Значення типів

- **SOLO** — тільки актуальний цільовий текст; REPORTS заборонені.
- **SOLO_CONTEXT** — цільовий текст + дозволені первинні файли/Git; REPORTS заборонені.
- **SOLO_POST_EDIT** — свіжа перевірка вже зміненого тексту; старі REPORTS заборонені.
- **DEPENDENT*** — читає тільки зазначені required/optional REPORTS.
- Якщо required REPORT відсутній — `BLOCKED`, без домислювання його результату.

№29 і №30 залишаються незалежними від попередніх висновків. O1 читає всю кампанію.


## AUTO DISPATCH ORDER

Для команди без ID dispatcher перевіряє задачі в такому порядку:

```text
01 → 02 → 03 → ... → 27 → D1 → K0
→ A1 → A2 → A3 → A4
→ 28
→ EDIT GATE
→ 29 → 30
→ O1
```

`31` **не** входить до auto-dispatch і запускається лише явною командою.

### Правило вибору

«Наступний» = перший ID у цьому порядку, який:
- не має COMPLETE report у поточному run;
- не має активного CLAIM;
- має всі required reports;
- має виконаний stage gate.

Report-файли timestamped. Для перевірки виконаності `04` шукай `04__*.md` і `04__retry-*__*.md`.

### EDIT GATE

Після COMPLETE report `28` автоматичний dispatcher **зупиняється**.

`29` стає runnable лише після того, як:
1. користувач/редактор реально вніс схвалені правки в target;
2. у `RUN.md` або окремому gate marker зафіксовано, що EDIT GATE пройдено;
3. поточний target blob SHA відрізняється або явно підтверджено, що правок не потрібно.

До цього коротка команда має повернути `WAITING_FOR_EDIT`, а не запускати 29.
