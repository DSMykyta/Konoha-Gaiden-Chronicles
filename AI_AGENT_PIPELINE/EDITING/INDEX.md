## Суфікс `-e`

Якщо task має хоча б один `required_report`, його ID і filename мають суфікс `-e`.

Приклади:
- незалежний: `29.md`;
- залежний: `30-e.md`;
- його report: `30-e.md`;
- його claim: `30-e.md`.

`-e` = task потребує інших report-файлів перед стартом.

## AUTO DISPATCH ORDER

```text
01 → 02 → ... → 28 → 29
→ 30-e → 31-e → 32-e → 33-e → 34-e
→ EDIT GATE
→ 35 → 36
→ 37-e
```

`38-e` не входить до auto-dispatch і запускається лише явно.

«Наступний» = перший ID у цьому порядку, який:
- не має COMPLETE report;
- не має активного CLAIM;
- має всі required reports;
- пройшов stage gate.

Після COMPLETE `34-e` dispatcher зупиняється на EDIT GATE. `35` стає runnable лише після фактичного застосування/підтвердження схвалених правок.

Фінальний основний report EDITING = `37-e.md`.


## Legacy `-e` transition

Якщо task був уже CLAIMED до введення суфікса `-e`, старий unsuffixed claim/report тимчасово вважається alias нового dependent ID.

Приклад:
- старий `30.md` claim = `30-e` зайнятий;
- не створюй паралельний `30-e` claim;
- якщо старий worker завершить `30.md`, перенеси його результат у `30-e.md` і видали legacy-файл/claim;
- після міграції використовуй тільки `30-e`.
