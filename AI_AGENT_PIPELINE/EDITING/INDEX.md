## Значення етапів

- **01–27** — незалежні аналізатори, тільки актуальний target.
- **28** — незалежна перевірка внутрішньої консистентності системи світу.
- **29** — незалежний контекстний пакет із первинних файлів/Git.
- **30** — фаєрвол припущень і галюцинацій.
- **31** — anti-edit / захисник чинного тексту.
- **32** — кластеризатор знахідок і кореляцій.
- **33** — контекстний фактчек.
- **34** — мета-арбітраж.
- **35** — свіжа незалежна перевірка після схвалених правок.
- **36** — коректура/післяредакторська перевірка після 35.
- **37** — фінальний оркестратор.
- **38** — додатковий фінальний синтез; тільки явний запуск.

## AUTO DISPATCH ORDER

Для команди без ID порядок тепер повністю числовий:

```text
01 → 02 → 03 → ... → 27 → 28 → 29
→ 30-e → 31-e → 32-e → 33-e → 34-e
→ EDIT GATE
→ 35 → 36
→ 37-e-e
```

`38-e` не входить до auto-dispatch і запускається лише явною командою.

### Правило вибору

«Наступний» = перший ID у цьому порядку, який:
- не має COMPLETE report у поточному run;
- не має активного CLAIM;
- має всі required reports;
- має виконаний stage gate.

Для повторного повного запуску того самого task можуть існувати `03.md`, `03__02.md`, `03__03.md`. Для auto-dispatch task вважається виконаним, якщо є хоча б один COMPLETE результат цієї серії.

### EDIT GATE

Після COMPLETE report `34-e` автоматичний dispatcher зупиняється.

`35` стає runnable лише після того, як:
1. користувач/редактор реально вніс схвалені правки в target;
2. у `RUN.md` або окремому gate marker зафіксовано, що EDIT GATE пройдено;
3. поточний target blob SHA відрізняється або явно підтверджено, що правок не потрібно.

До цього коротка команда має повернути `WAITING_FOR_EDIT`, а не запускати 35.

### Фінал

`37-e` — останній автоматичний етап і фінальний результат основного EDITING pipeline.

`38-e` — лише за прямою командою користувача.
