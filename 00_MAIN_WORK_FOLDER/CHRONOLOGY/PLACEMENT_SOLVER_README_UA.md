# Автоматична перевірка сюжетної хронології

Ця підсистема **не змінює** SITE, сцен, якірних дат або канон. Вона читає чинні YAML у `data/`, порівнює прийняті `before`-зв'язки, фізичну присутність персонажів, місії з `mission-windows.yaml` і географію, після чого створює звіт.

## Запуск

З кореня репозиторію:

```sh
python -m pip install PyYAML
python -m unittest discover -s 00_MAIN_WORK_FOLDER/CHRONOLOGY/tests -p 'test_placement_solver.py' -v
python 00_MAIN_WORK_FOLDER/CHRONOLOGY/placement_solver.py \
  --report 00_MAIN_WORK_FOLDER/CHRONOLOGY/PLACEMENT_AUDIT_UA.md \
  --json 00_MAIN_WORK_FOLDER/CHRONOLOGY/PLACEMENT_AUDIT.json
```

Опціонально для глобального узгодження декількох пропонованих дат:

```sh
python -m pip install ortools
```

Якщо OR-Tools недоступний, інструмент усе одно аналізує календар та виводить обґрунтовані інтервали (але не перевіряє глобальну оптимальність розкладу). Стандартний режим не завершується помилкою через вже відомі суперечності, а фіксує їх. `--strict` повертає ненульовий статус для підтверджених структурних конфліктів.

## Як дозволити пропозицію нової дати

`placement-windows.yaml` спочатку порожній. Перш ніж записувати в нього щось, потрібно мати підставу з історії чи джерела. Наприклад, структура **без конкретних дат**:

```yaml
windows:
  - scene_id: sc-some-undated-scene
    not_before: {year: YEAR, month: MONTH, day: DAY}
    not_after: {year: YEAR, month: MONTH, day: DAY}
    preferred: {year: YEAR, month: MONTH, day: DAY} # необов'язково
constraints:
  - id: confirmed-travel-interval
    kind: min_gap_days
    a: sc-previous-scene
    b: sc-next-scene
    days: VERIFIED_TRAVEL_DAYS
    review: accepted
```

Цей приклад — **не справжні дані** й не готовий до запуску. Проміжки `not_before` / `not_after` включні. `before` за замовчуванням означає календарно не пізніше (події можуть бути в один день); якщо джерело доводить різні дні або дорогу, вказуйте підтверджений `min_gap_days`.

За двосторонніх меж система знаходить допустимі дні. Якщо їх декілька і немає доведеного бажаного дня, вона **не призначає випадкову дату**. З OR-Tools CP-SAT може побудувати узгоджений робочий сценарій, але він теж не стає автоматично прийнятим каноном.

## Категорії висновків

- **Структурний конфлікт:** порушено прийнятий порядок або неможливо виконати визначене резервування місій.
- **Підозра:** той самий персонаж у двох відомих країнах протягом календарного дня, але відсутні години та доказ неможливості переходу.
- **Дозволена паралельність:** різні групи можуть діяти того самого дня, якщо фізично не перетинаються.
- **Невідомо:** відсутні достатні межі, географічні або джерельні відомості.
- **Пропозиція:** допустимий день у межах доказового вікна, без зміни вихідного YAML.

Система ще **не витягає сцени автоматично з необроблених літературних логів**. Нові ігри спочатку треба розмітити на події, учасників, місця та підтверджені часові зв'язки; після цього вони беруть участь у перевірці.

## Редакторська дисципліна

Не переписувати затверджені якорі заради рівномірності шкали. Не прирівнювати згадку чи remote-участь до фізичної присутності. Не об'єднувати альтернативні фільми з основною тяглістю без підтверджень. Перевірені зміни до вихідних сцен окремо вносять до `EDITORIAL_DECISIONS_UA.md` за правилами `AGENTS.md`. Коміт не викликає деплой сайту.
