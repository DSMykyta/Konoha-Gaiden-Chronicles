# Зображення подій і вікові профілі

Джерело всіх доповнень: `KONOHA_GAIDEN_ARCS_ZIGRANE_POV_V3/CHRONOLOGY/data/`.
Після коміту в `main` Vercel збирає доповнення разом із хронологією. Сайт лише читає їх.

## Фото над заголовком події

`event-media.yaml` містить записи, зв'язані через точний `event_id` із `scenes/*.yaml`.
Сам файл кадру лежить у `data/media/events/`. Зображення показуються над заголовком;
кілька кадрів можна гортати горизонтально. Відсутність фото не створює порожнього блоку.

```yaml
schema_version: 1
media:
  - id: img-UNIQUE-ID
    event_id: ev-EXACT-EVENT-ID
    src: media/events/ev-EXACT-EVENT-ID/frame.jpg
    alt: Короткий опис того, що справді видно в кадрі
    caption: Підпис зображення
    source_id: src-EXISTING-SOURCE-ID
    kind: anime
    locator: "Naruto, серія NN, 00:MM:SS.mmm"
    coverage: event
    status: published
    order: 0
```

`source_id` береться з джерел, уже прив'язаних до події через `evidence_ids`.
Локатор має містити **точну серію й час** або **главу, сторінку й панель**.
`coverage: canonical_part` означає, що кадр ілюструє канонічну частину змішаної події.
Наприклад, кадр наради з аніме не доводить присутність Райдо, додану в історії проєкту.
`candidate` зберігає запропоновану прив'язку; `published` показує її на сайті.

## Механізм для моделі

Усі команди виконуються з папки `SITE`. Модель отримує невеликий пакет із точним ID,
описом і джерелами, потім працює з однією подією за раз.

1. Отримати завдання:

   ```sh
   node scripts/media.mjs tasks --event ev-y0-0624-jonin-nominate-teams
   # або наступні 5 подій без зображень
   node scripts/media.mjs tasks --limit 5
   ```

2. Відкрити доступну серію/сторінку з указаного джерела. Знайти точну дію,
   прочитати навколишній контекст, записати локатор. Якщо доступу немає або
   точне місце невідоме — залишити завдання незаповненим; часову мітку не вигадувати.

3. Отримати кадр і зареєструвати його одним із способів:

   ```sh
   # З готового скріншота аніме або панелі манги
   node scripts/media.mjs attach --event EVENT_ID --source SOURCE_ID \
     --input /absolute/path/frame.png --locator "точний локатор" \
     --alt "що видно в кадрі" --caption "підпис"

   # Витягнути один кадр із локального відео (потрібен ffmpeg)
   node scripts/media.mjs attach --event EVENT_ID --source SOURCE_ID \
     --video /absolute/path/episode.mp4 --at 00:05:18.400 \
     --locator "Naruto, серія NN, 00:05:18.400" --alt "що видно в кадрі"

   # Завантажити конкретне доступне HTTPS-зображення
   node scripts/media.mjs attach --event EVENT_ID --source SOURCE_ID \
     --url https://example.org/exact-frame.jpg \
     --locator "глава NN, сторінка NN, панель N" --alt "що видно в панелі"
   ```

   Скрипт перевіряє ID, джерело, справжній тип зображення й розмір, створює
   стабільне ім'я файлу та запис `candidate`. Повтор тієї самої картинки не створює дубль.
   Відео й облікові дані в репозиторій не потрапляють.

4. Візуально перевірити отриманий кадр проти **дії**, а не тільки облич персонажів.
   Для змішаної події явно підписати канонічну частину. Потім:

   ```sh
   node scripts/media.mjs publish --id RETURNED_IMAGE_ID --verified
   npm run build
   ```

5. В одному коміті додати `event-media.yaml` і файл кадру. Не змінювати текст сцени,
   щоб він відповідав знайденій картинці. Фото має відповідати вже заданій події.

### Готовий промпт для слабкої моделі

> Виконай одну прив'язку кадру до події. Спершу запусти `media.mjs tasks --event ID`.
> Прочитай title, text і evidence. Знайди зображення лише в доступному джерелі цієї
> події. Для аніме запиши серію і точний час; для манги — главу, сторінку й панель.
> Відкрий зображення й перевір, що воно показує потрібну дію. Не підставляй портрет,
> обкладинку або схожий бій. Не вигадуй час і не змінюй подію. Для доповнень історії
> проєкту не приписуй кадру того, чого в ньому немає; використовуй canonical_part.
> Запусти attach, переглянь збережений кадр і лише після відповідності — publish.
> Запусти build. Коміт має містити один запис і його файл. Якщо джерело недоступне
> або відповідність не доведена, поверни ID події та конкретну відсутню інформацію.

## Персонажі та вікові вкладки

`character-profiles.yaml` підтримує будь-який `entity_id` і довільну кількість вікових
версій. Кожна наступна вікова версія описує лише зміни відносно попередньої.
Якщо поле в новій версії не записане, сайт успадковує його з попереднього віку.
При перемиканні вкладки фото й дані складаються з успадкованої бази та змін,
заданих для поточної версії. Пізніші дані ніколи не переносяться назад у ранні версії.

Профіль відкривається стрілкою праворуч від імені в меню ліній або ім'ям у картці події.
На миші стрілка з'являється при наведенні чи фокусі; на телефоні вона завжди видима.

Повний рекомендований шаблон вікової версії:

```yaml
profiles:
  - entity_id: c-naruto
    display_name: Наруто Узумакі
    versions:
      - id: naruto-12
        label: "12 років"
        age: 12

        # Часова прив'язка версії. Заповнюється лише якщо межі відомі.
        from_year: 0
        to_year: 0
        period_id: part-i

        # Власне фото саме цієї вікової версії.
        image: media/profiles/naruto-12.jpg
        image_alt: Наруто Узумакі у віці 12 років

        # Короткий опис стану персонажа саме в цьому періоді.
        summary: |
          Повний затверджений опис персонажа цього віку.
          Не додавати сюди знання або зміни з пізніших періодів.

        # Короткі структуровані факти. Сюди належать, зокрема, ранг,
        # село, день народження, зріст, вага, група крові, класифікація.
        facts:
          - {key: village, label: "Село", value: "Конохаґакуре"}
          - {key: rank, label: "Ранг", value: "генін"}

        # Зовнішність саме цього віку.
        appearance:
          hair: "опис волосся"
          eyes: "опис очей"
          features: "характерні риси"
          clothing: "одяг цього періоду"

        # Риси характеру, актуальні для цієї версії.
        traits:
          - "риса характеру"

        # Поточні цілі персонажа.
        goals:
          - "актуальна ціль"

        # Лише здібності, які вже доступні або реально опановуються
        # в межах цієї вікової версії.
        abilities:
          - {name: "Назва техніки", status: "статус у цьому періоді"}

        # Стосунки — тільки ті, що існують або відомі персонажу в цей період.
        # Батьки теж належать до цього блоку за змістом, але якщо для картки
        # потрібне окреме видиме поле «Батьки», його можна дублювати у facts.
        relationships:
          - {entity_id: "c-example", label: "тип або стан стосунків"}

        # Приклад вікової логіки для батьків:
        # у ранній версії Наруто:
        #   - {key: parents, label: "Батьки", value: "сирота"}
        # у пізнішій версії, коли походження вже відоме:
        #   - {key: parents, label: "Батьки", value: "Мінато Намікадзе та Кушина Узумакі"}

        # Спорядження саме цього періоду.
        equipment:
          - "предмет спорядження"

        # Довільні додаткові блоки, якщо інформація не вкладається
        # в основну структуру.
        sections:
          - title: "Назва додаткового розділу"
            text: "затверджений текст"

      - id: naruto-13
        label: "13 років"
        age: 13

        # Записуємо тільки те, що змінилося.
        # village, birthday, parents, eyes тощо автоматично
        # успадковуються з naruto-12, якщо тут їх немає.
        facts:
          - {key: rank, label: "Ранг", value: "генін"}

        appearance:
          clothing: "новий одяг цього віку"

        abilities:
          - {name: "Расенґан", status: "опанована"}
```

Правила заповнення:

- Версії йдуть у хронологічному порядку. Кожна наступна версія автоматично успадковує
  всі відсутні поля з попередньої.
- Скалярне поле (`image`, `summary`, `age` тощо) змінюється лише якщо воно явно
  записане в новій версії.
- `appearance` успадковується по ключах: можна змінити лише `clothing`, не повторюючи
  `hair` та `eyes`.
- `facts` зливаються за `key`, `abilities` — за `name`, `relationships` — за
  `entity_id`, `sections` — за `title`. Запис із тим самим ключем оновлює попередній,
  новий ключ додається.
- `traits`, `goals` та `equipment` успадковуються цілком, якщо поле відсутнє.
  Якщо поле явно записане — його список замінює попередній.
- Тому в новому віці не дублюються незмінні батьки, село, зовнішність, спорядження тощо:
  записуються лише фактичні зміни.
- `facts` використовується для коротких видимих полів картки. Якщо важлива інформація
  має окремий підпис у UI — наприклад «Батьки» — вона записується сюди.
- `relationships` зберігає змістовні зв'язки з іншими персонажами. Не слід додавати
  стосунок раніше, ніж він фактично існує або стає відомим у хронології.
- Для здібностей важливий не лише перелік, а й їхній стан у цьому віці:
  `опанована`, `опановує`, `нестабільний доступ` тощо.
- Якщо дані не змінилися — поле треба **не записувати**: тоді воно успадкується.
  Порожній масив, порожній об'єкт або `null` слід використовувати лише коли треба
  свідомо очистити/скинути значення, а не як позначку «невідомо».
- Вік не вираховується з робочих дат, а біографічні факти не вигадуються.
- Інші персонажі можуть мати загальний профіль і статистику з хронології, доки для них
  не додано окремі вікові версії.

## Керування хронологією

- Початково обрані всі персонажі поточної історичної лінії.
- Обрати/зняти всіх діє на весь список, навіть коли використано пошук персонажа.
- У детальному масштабі показуються лінії з подіями у видимому періоді.
  Довге полотно можна рухати вертикально перетягуванням або смугою прокручування.
- Натискання на лінію/ім'я приглушує інших і залишає події обраного персонажа.
- Стрілки біля імені у фокусі та в картці рухаються між його подіями.
  Без фокуса картка переходить між подіями обраних ліній.
- Порядок усередині дня задається display_rank; він не встановлює точну годину.
- Чергування тла прив'язане до календарних меж днів, включно з днями без подій.
- Повернення у вкладку та перевірка раз на хвилину підхоплюють нову ревізію даних
  без скидання вибору й фокуса. Невдалий запит зберігає поточні завантажені дані.
- Пряме посилання: `/?event=EVENT_ID&character=ENTITY_ID`.
